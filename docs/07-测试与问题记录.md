## 7.3 构建环境踩坑记录（真实问题，非示例）

### 问题 1：AGP 拒绝中文路径

- **现象**：`assembleDebug` 直接失败，
  报 `Your project path contains non-ASCII characters. This will most likely cause the build to fail on Windows.`
- **原因**：本机用户目录是 `C:\Users\郭祉谦\...`，AGP 出于历史原因默认拒绝非 ASCII 工程路径。
- **解决**：在 `gradle.properties` 中加 `android.overridePathCheck=true`，并注释说明原因。
- **经验**：AGP 8.x 实际已能正确处理 UTF-8 路径，这个检查是保守的历史遗留；但**不要在陌生机器上随便加**，
  加之前先确认失败原因就是这条。

### 问题 2：Kotlin 编译器把路径写成 `\uXXXX` 转义

- **现象**：资源合并通过后，`compileDebugKotlin` 报一串
  `error: source file or directory not found: C:\Users\u90EDu7949u8C26\...\CsmApp.kt`，
  路径里的中文被转成了 `\u90ED\u7949\u8C26` 字面量。
- **原因**：Windows + 非 ASCII 路径下，Kotlin 编译任务通过参数文件传源文件列表，
  参数文件写入时把非 ASCII 字符转义，读取端没有还原，编译器就去找字面量路径。
- **解决**：`gradle.properties` 加 `kotlin.compiler.execution.strategy=in-process`，
  改为 Gradle 进程内直接调用编译器，路径作为 JVM 参数以 Unicode 传递，不再经过参数文件。
- **经验**：这类问题的通用解法是「让路径不经过文本中转」，而不是去改文件名或代码。

### 问题 3：改 `gradle.properties` 把中文注释写坏

- **现象**：用 PowerShell 的 `Set-Content` 追加内容后，原有中文注释变成乱码，
  且 `android.overridePathCheck=true` 被拼进了注释行，构建再次失败。
- **原因**：读写两端编码不一致（ANSI/UTF-8），且 `-Raw` + `Set-Content` 处理换行时合并了行尾。
- **解决**：改用编辑器整体重写该文件，统一 UTF-8（无 BOM）。
- **经验**：**含中文的配置文件一律整体重写，不要用脚本做 read-modify-write**。

### 问题 4：Vector 图标在低版本上 tint 失效

- **现象**：`android:tint="?attr/colorControlNormal"` 在部分 API 24 设备上不生效。
- **解决**：去掉 vector 内部的 `android:tint`，改由使用处（`app:tint`）统一着色，
  `fillColor` 用白色，兼容 AppCompat 的 vector 兼容路径。

### 问题 5：删除属性行导致 XML 结构损坏

- **现象**：批量删 `android:tint` 行后，`<vector>` 标签少了闭合的 `>`，资源编译失败。
- **解决**：用正则把 `android:viewportHeight="24"` 后补回 `>`；此后所有批量改写都先 `aapt` 校验再继续。
- **经验**：批量正则改 XML 是高风险操作，改完必须编译验证，不要连续改多个文件后再一起试。

### 问题 6：Gradle 发行包地址在本机不可达

- **现象**：`gradlew assembleDebug` 卡在 `Downloading https://services.gradle.org/distributions/gradle-8.11.1-bin.zip` 直到超时
  （curl 直接返回 `000`，连接阶段就断了；Android Studio 首次 Sync 同样会卡死在这里）。
- **诊断**：不是项目问题——`https://services.gradle.org` 与 `downloads.gradle.org` 在本机网络下连不上，
  而 `https://mirrors.cloud.tencent.com/gradle/gradle-8.11.1-bin.zip` 返回 200、完整下载无损坏。
- **解决**：把 `gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 改为腾讯云镜像，
  并在文件里用注释写明"镜像失效时改回官方地址"；下载完成后校验通过，`gradle --version` 显示 Gradle 8.11.1。
- **经验**：只改 wrapper 的下载地址，不改版本号——版本变了 `libs.versions.toml` 里的 AGP/Kotlin 兼容矩阵都要重验。

### 问题 7：`testDebugUnitTest` 起不来（`ClassNotFoundException: GradleWorkerMain`）

- **现象**：`gradlew testDebugUnitTest` 直接失败，日志为
  `错误: 找不到或无法加载主类 worker.org.gradle.process.internal.worker.GradleWorkerMain`
  以及 `Could not write standard input to Gradle Test Executor 1: java.io.IOException: 管道正在被关闭。`
  `assembleDebug` 完全正常，只有测试任务挂。
- **诊断**：Gradle 会为每个测试任务 fork 一个 JVM（Test Executor），把工作进程的 classpath 拼在启动参数里。
  本机的 Gradle 用户目录是 `C:\Users\郭祉谦\.gradle`，路径里有中文；JVM 启动参数按平台编码解析，
  中文被写坏后连 `gradle-worker-main-8.11.1.jar` 都定位不到，于是报"找不到主类"。
  排查过程：① 把工程复制到纯英文路径 `D:\android csm` → 仍失败（说明不是工程路径的问题）；
  ② 用纯英文路径下解压的 Gradle 发行版 → 仍失败（说明不是发行版路径的问题）；
  ③ 把 Gradle 用户目录切到纯英文 `D:\gh` → **一次通过，6/6 用例 OK**（`TEST-com.csm.market.core.ui.UiStateTest.xml`：tests=6 failures=0）。
- **解决**：对含中文用户名的机器，把 Gradle 用户目录指向纯英文路径即可：
  - 命令行：`set GRADLE_USER_HOME=D:\AndroidGradle` 后再执行 `gradlew test`；
  - Android Studio：`Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle user home`
    填 `D:\AndroidGradle`，重新 Sync。
- **验证**：切换后 `testDebugUnitTest` BUILD SUCCESSFUL，报告 6 个用例全绿；
  直接用 `JUnitCore` 手工执行同一批 class 也是 `OK (6 tests)`，两边结论一致。
- **经验**：Windows 上"中文用户名 + Gradle 测试任务"是已知雷区；工程路径英文、用户目录英文，两项都要满足。
