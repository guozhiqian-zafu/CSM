## 7.3 构建环境踩坑记录（真实问题，非示例）

### 问题 1：AGP 拒绝中文路径

- **现象**：`assembleDebug` 直接失败，
  报 `Your project path contains non-ASCII characters. This will most likely cause the build to fail on Windows.`
- **原因**：本机用户目录是 `C:\Users\郭祉谦\...`，AGP 出于历史原因默认拒绝非 ASCII 工程路径。
- **解决**：在 `gradle.properties` 中加 `android.overridePathCheck=true`，并注释说明原因。
- **经验**：AGP 8.x 实际已能正确处理 UTF-8 路径，这个检查是保守的历史遗留；但**不要在陌生机器上随便加**，
  加之前先确认失败原因就是这条。

### 问题 2：Kotlin 编译器把路径写成 `\uXXXX` 转义

- **现象**：资源合并通过后，`compileDebugKotlin` 报一串
  `error: source file or directory not found: C:\Users\u90EDu7949u8C26\...\CsmApp.kt`，
  路径里的中文被转成了 `\u90ED\u7949\u8C26` 字面量。
- **原因**：Windows + 非 ASCII 路径下，Kotlin 编译任务通过参数文件传源文件列表，
  参数文件写入时把非 ASCII 字符转义，读取端没有还原，编译器就去找字面量路径。
- **解决**：`gradle.properties` 加 `kotlin.compiler.execution.strategy=in-process`，
  改为 Gradle 进程内直接调用编译器，路径作为 JVM 参数以 Unicode 传递，不再经过参数文件。
- **经验**：这类问题的通用解法是「让路径不经过文本中转」，而不是去改文件名或代码。

### 问题 3：改 `gradle.properties` 把中文注释写坏

- **现象**：用 PowerShell 的 `Set-Content` 追加内容后，原有中文注释变成乱码，
  且 `android.overridePathCheck=true` 被拼进了注释行，构建再次失败。
- **原因**：读写两端编码不一致（ANSI/UTF-8），且 `-Raw` + `Set-Content` 处理换行时合并了行尾。
- **解决**：改用编辑器整体重写该文件，统一 UTF-8（无 BOM）。
- **经验**：**含中文的配置文件一律整体重写，不要用脚本做 read-modify-write**。

### 问题 4：Vector 图标在低版本上 tint 失效

- **现象**：`android:tint="?attr/colorControlNormal"` 在部分 API 24 设备上不生效。
- **解决**：去掉 vector 内部的 `android:tint`，改由使用处（`app:tint`）统一着色，
  `fillColor` 用白色，兼容 AppCompat 的 vector 兼容路径。

### 问题 5：删除属性行导致 XML 结构损坏

- **现象**：批量删 `android:tint` 行后，`<vector>` 标签少了闭合的 `>`，资源编译失败。
- **解决**：用正则把 `android:viewportHeight="24"` 后补回 `>`；此后所有批量改写都先 `aapt` 校验再继续。
- **经验**：批量正则改 XML 是高风险操作，改完必须编译验证，不要连续改多个文件后再一起试。

### 问题 6：Gradle 发行包地址在本机不可达

- **现象**：`gradlew assembleDebug` 卡在 `Downloading https://services.gradle.org/distributions/gradle-8.11.1-bin.zip` 直到超时
  （curl 直接返回 `000`，连接阶段就断了；Android Studio 首次 Sync 同样会卡死在这里）。
- **诊断**：不是项目问题——`https://services.gradle.org` 与 `downloads.gradle.org` 在本机网络下连不上，
  而 `https://mirrors.cloud.tencent.com/gradle/gradle-8.11.1-bin.zip` 返回 200、完整下载无损坏。
- **解决**：把 `gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 改为腾讯云镜像，
  并在文件里用注释写明"镜像失效时改回官方地址"；下载完成后校验通过，`gradle --version` 显示 Gradle 8.11.1。
- **经验**：只改 wrapper 的下载地址，不改版本号——版本变了 `libs.versions.toml` 里的 AGP/Kotlin 兼容矩阵都要重验。

### 问题 7：`testDebugUnitTest` 起不来（`ClassNotFoundException: GradleWorkerMain`）

- **现象**：`gradlew testDebugUnitTest` 直接失败，日志为
  `错误: 找不到或无法加载主类 worker.org.gradle.process.internal.worker.GradleWorkerMain`
  以及 `Could not write standard input to Gradle Test Executor 1: java.io.IOException: 管道正在被关闭。`
  `assembleDebug` 完全正常，只有测试任务挂。
- **诊断**：Gradle 会为每个测试任务 fork 一个 JVM（Test Executor），把工作进程的 classpath 拼在启动参数里。
  本机的 Gradle 用户目录是 `C:\Users\郭祉谦\.gradle`，路径里有中文；JVM 启动参数按平台编码解析，
  中文被写坏后连 `gradle-worker-main-8.11.1.jar` 都定位不到，于是报"找不到主类"。
  排查过程：① 把工程复制到纯英文路径 `D:\android csm` → 仍失败（说明不是工程路径的问题）；
  ② 用纯英文路径下解压的 Gradle 发行版 → 仍失败（说明不是发行版路径的问题）；
  ③ 把 Gradle 用户目录切到纯英文 `D:\gh` → **一次通过，6/6 用例 OK**（`TEST-com.csm.market.core.ui.UiStateTest.xml`：tests=6 failures=0）。
- **解决**：对含中文用户名的机器，把 Gradle 用户目录指向纯英文路径即可：
  - 命令行：`set GRADLE_USER_HOME=D:\AndroidGradle` 后再执行 `gradlew test`；
  - Android Studio：`Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle user home`
    填 `D:\AndroidGradle`，重新 Sync。
- **验证**：切换后 `testDebugUnitTest` BUILD SUCCESSFUL，报告 6 个用例全绿；
  直接用 `JUnitCore` 手工执行同一批 class 也是 `OK (6 tests)`，两边结论一致。
- **经验**：Windows 上"中文用户名 + Gradle 测试任务"是已知雷区；工程路径英文、用户目录英文，两项都要满足。

## 7.7 问题记录（第 5 次提交新增）

### 问题 8：PowerShell 里 `curl --data-binary '{"..."}'` 会让服务端「误报」JSON 非法

- **现象**：联调 `POST /api/products` 时，无论请求体写得多完整，服务端一律回
  `{"code":1001,"message":"请求体不是合法的商品 JSON"}`，一开始怀疑 kotlinx 反序列化配置有问题。
- **诊断**：把同一段 JSON 用 `[System.IO.File]::WriteAllText(path, json, UTF8NoBOM)` 写成文件，
  再用 `--data-binary "@file"` 发送，接口立刻返回 201。说明问题在命令行而不是服务端。
  原因是 PowerShell 会解析并传参给定原生命令，内联 JSON 里的双引号在传参途中被吞掉，
  curl 实际发出的是 `{title:desk lamp,...}` 这种非法 JSON。
- **解决**：约定联调脚本一律「UTF-8 文件 + `@file`」，避免手写引号；
  另外服务端补了 `Throwable.findMissingFields()`，顺着 cause 链找 kotlinx 的 `MissingFieldException`，
  缺字段时直接回 `缺少必填字段：category、condition`，比笼统的「不是合法 JSON」好排查得多。
- **经验**：接口「一直报同一个错」时，先确认请求真的长成自己以为的样子（抓包或落盘），
  再怀疑服务端；Windows 命令行 + 中文 + JSON 是最容易自我欺骗的组合。

### 问题 9：Netty 的 DEBUG 日志把业务输出淹没

- **现象**：服务端启动后日志每秒刷几十行 `io.netty.buffer.*` 的 `-Dxxx` 参数，看不到 `Responding at` 之前的业务信息。
- **解决**：新增 `server/src/main/resources/logback.xml`，root 定为 `INFO`，`io.netty` 压到 `WARN`，
  自定义格式 `%d{HH:mm:ss.SSS} %-5level %logger{28} - %msg%n`。
- **经验**：日志级别本身也是「可运维性」的一部分，演示时满屏 DEBUG 会显得项目不专业。

### 问题 10：8080 端口被占用导致服务端起不来

- **现象**：`:server:run` 抛 `java.net.BindException: Address already in use: bind`，
  但访问本机 8080 的 `/health` 返回 404（被另一个进程占着）。
- **解决**：`Application.port()` 读环境变量 `CSM_PORT`，演示/联调时用 `CSM_PORT=18080` 启动，不改代码。
- **经验**：端口、数据库路径、密钥这类「环境相关」的值都从环境变量或配置文件读，代码里只留默认值。
## 问题 11：Ktor 路由里 `call` 未解析

- 现象：新增 `server/.../Uploads.kt` 后 `:server:compileKotlin` 报 `Unresolved reference 'call'`，报错行包括
  `call.receiveMultipart()`、`call.parameters`、`call.respondFile(...)`。
- 原因：Ktor 2 的 `call` 不是路由 DSL 的成员，而是 `ApplicationCall` 的扩展属性，位于
  `io.ktor.server.application` 包，必须显式 `import io.ktor.server.application.call`。
- 解决：补上该 import 后编译通过。
- 经验：Ktor 2 里很多「看起来是成员」的东西其实是扩展（`call`、`respondText` 等同理），报未解析时先查包。

## 问题 12：单元测试的假仓库要跟着接口一起长

- 现象：`ProductRepository` 新增 `publish(...)` 后，`HomeViewModelTest` 里的 `FakeProductRepository`
  编译失败：`Class 'FakeProductRepository' is not abstract and does not implement abstract member 'publish'`。
- 原因：接口加方法，所有测试替身都要同步实现；这类错误只在 `testDebugUnitTest` 编译时暴露，
  `assembleDebug` 不会报（测试源码不参与 APK 构建）。
- 解决：给替身补 `override suspend fun publish(...) = error("首页用例不会调用 publish")`，
  并在 `uploadImage` 的假实现里记录文件名，用来断言「几张图就上传几次」。
- 经验：改 `data/repo` 的接口后，先跑一次 `testDebugUnitTest` 再提交，能第一时间暴露替身遗漏。
## 问题 13：新增 library 模块后根工程报「插件已在 classpath 上」

- **现象**：新建 `companion/` 模块（`com.android.library`）后构建失败：
  `Error resolving plugin [id: 'com.android.library', version: '8.9.1'] > The request for this plugin could not be satisfied because the plugin is already on the classpath with an unknown version`。
- **原因**：根 `build.gradle.kts` 只声明了 `android.application` 的 `apply false`；
  子模块再单独请求 `com.android.library` 并带版本号时，Gradle 发现 AGP 已经在 classpath 上（由 application 插件带入），
  版本信息不明确，于是拒绝再解析一次。
- **解决**：在根 `plugins {}` 里补 `alias(libs.plugins.android.library) apply false`，
  并在 `gradle/libs.versions.toml` 的 `[plugins]` 加 `android-library = { id = "com.android.library", version.ref = "agp" }`。
- **经验**：所有「多模块共用」的 Gradle 插件都应在根工程统一声明版本、`apply false`，子模块只 `alias(...)` 不带版本。

## 问题 14：`registerForActivityResult` 不能写在 `onResume` 里

- **现象**：为申请通知权限，最初把 `registerForActivityResult(...).launch(...)` 写进 `onResume`，运行时会抛
  `LifecycleOwner is attempting to register while current state is RESUMED`。
- **原因**：Activity Result API 要求在组件进入 `STARTED` 之前完成注册，否则返回栈恢复时无法定位回调。
- **解决**：把 `registerForActivityResult` 写成 Activity 的属性初始化（构造期注册），需要时只调用 `.launch(...)`；
  再用 SharedPreferences 标记「问过一次」，避免每次进首页都打扰用户。
- **经验**：一切「注册回调」类 API（ActivityResult、MenuProvider、LifecycleObserver）都遵循「先注册、后触发」。

## 问题 15：小组件不能在里面发网络请求

- **现象**：最初想让 `MarketWidgetProvider.onUpdate` 直接查未读数，结果要么拿不到结果，要么拖慢桌面刷新。
- **原因**：`AppWidgetProvider.onUpdate` 是广播回调，主线程只有约 10 秒预算，且进程随时可能被回收；
  在里面做网络请求既容易超时，也会让桌面卡顿。
- **解决**：未读数由主 App 在调用 `/api/messages/unread-count` 成功后写入 SharedPreferences，
  小组件通过 `content://com.csm.market.widget/summary` 同步读取这份缓存；真正的周期刷新交给
  `updatePeriodMillis`（30 分钟兜底）与主 App 的 `requestUpdate()`。
- **经验**：组件（小组件/通知/快捷方式）只做「读现成数据 + 渲染」，数据准备放在有生命周期的组件里。
