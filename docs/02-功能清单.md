## 2.2 对照课程「最低复杂度标准」

| 课程要求 | 本项目对应实现 | 是否满足 |
| --- | --- | --- |
| ≥ 4 个界面，含「列表 → 详情」导航 | 首页列表、详情、发布、收藏、我的、搜索、留言（7 个），Navigation 单 Activity | ✅ |
| 数据持久化（Room / DataStore / 文件） | Room（商品缓存、收藏、留言）+ DataStore（最近搜索、设置） | ✅ |
| 至少一项硬能力 | 网络（Retrofit 调真实 API）+ 设备能力（相机、定位）+ 后台任务（WorkManager）三项都有 | ✅ |
| 协程 + ViewModel，无内存泄漏与主线程阻塞 | 每个页面一个 ViewModel，`viewModelScope`，Fragment 用 `viewLifecycleOwner` 收集 | ✅ |
| 权限申请与降级 | 相机拒绝→仅相册；定位拒绝→默认排序 + 提示条；均有替代路径 | ✅ |
| 至少一个自定义业务逻辑模块 | 智能定价助手（估价 + 评分 + 捡漏判定），见 `docs/06` | ✅ |
| 加载态 / 空态 / 错误态完整 | 每个列表与详情页面三态齐全（提交 2 起） | ✅ |

## 2.3 自选功能 / 伴生模块（P1 桌面小组件）

| 项 | 设计 |
| --- | --- |
| 形态 | 4×2 桌面小组件，主屏展示「我发布的 / 我收藏的 / 未读留言」三个数字 + 最新一条收藏 |
| 数据来源 | 只读主 App 的 Room 数据库（通过 `companion` 模块共享 `:core-data` 的 DAO，或 ContentProvider 暴露） |
| 交互 | 点数字 → 深链跳主 App 对应页面（`csm://market/list?tab=favorites`） |
| 刷新 | 本地数据变化时主动 notify；WorkManager 每 6 小时兜底刷新；点按手动刷新 |
| 独立验收 | 可单独装到桌面、断网可用（读本地库）、主 App 未登录时展示引导文案 |
| 异常处理 | 主 App 数据为空显示引导；数据库被卸载/清空时降级到空态而不是崩溃 |

详细设计见 [08-伴生模块设计.md](08-伴生模块设计.md)。

## 2.4 功能与提交的对应关系

15 次提交不是把功能平均切 15 段，而是按「骨架 → 数据 → 网络 → 特色功能 → 打磨 → 交付」推进，
每个大功能拆成 UI / 逻辑 / 联调多次提交，保证每次提交都能编译运行。详见
[05-开发计划与提交记录.md](05-开发计划与提交记录.md)。
