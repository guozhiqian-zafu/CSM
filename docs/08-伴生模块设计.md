# 08 伴生模块设计（P1 桌面小组件）

## 8.1 定位

伴生模块是 1 学分《移动互联网应用开发实战》的评分对象，评价标准是「小而完整、可独立演示」，
而不是第二个完整 App。因此它只做一件事：**把主 App 里最需要被看见的三个数字放到桌面上。**

| 项 | 内容 |
| --- | --- |
| 形态 | 4×2 AppWidget，主屏常驻 |
| 展示 | 我发布的（数量）、我收藏的（数量）、未读留言（数量）+ 最新一条收藏的标题 |
| 入口 | 桌面长按 → 小组件 → 校园集市；或主 App「设置 → 添加桌面小组件」引导 |
| 触发 | 点数字 → 深链进主 App 对应页；点刷新图标 → 立即刷新 |
| 数据 | 读主 App 的 Room 数据库（同进程外通过 ContentProvider 暴露只读查询） |

## 8.2 为什么选 P1

- 课程 B1 强制技术点包含「权限 + 云存储」，P1 不重复这些，而是补上**跨进程/跨入口的数据打通**；
- AppWidget 是 Android 特有、易被忽略的能力，`RemoteViews` 的限制（不能随便用自定义 View、
  不能直接跑网络）本身就是很好的工程训练；
- 演示成本低：装完直接放桌面就能看到效果，适合 3 分钟录屏。

## 8.3 架构

```
┌──────────────────────────────┐        ┌─────────────────────────────┐
│ 主 App（com.csm.market）      │        │ 伴生模块（com.csm.market.wg）│
│                              │        │                             │
│  Room: products/favorites/   │◄───────┤ CsmWidgetProvider           │
│        messages              │  query │   ├─ RemoteViews 渲染        │
│  ContentProvider:            │        │   ├─ 手动刷新按钮            │
│    content://com.csm.market. │        │   └─ 深链 PendingIntent      │
│    widget/summary            │───────►│                             │
│  变更时 notifyChange(uri)     │ notify │ WorkManager 兜底刷新(6h)     │
└──────────────────────────────┘        └─────────────────────────────┘
```

- **只读**：小组件不写主 App 数据，避免跨进程写冲突；
- **ContentProvider 而不是共享数据库文件**：跨进程直接开 Room 文件有锁与版本耦合风险，
  Provider 是 Android 官方推荐的跨应用数据共享方式，还能顺便支持「只暴露必要字段」；
- **notification**：主 App 里收藏/留言变化时调用 `contentResolver.notifyChange()`，
  小组件立即刷新，不需要轮询。

## 8.4 数据契约

`content://com.csm.market.widget/summary` 返回一行：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `listings_count` | INTEGER | 我发布的在售商品数 |
| `favorites_count` | INTEGER | 我收藏的商品数 |
| `unread_count` | INTEGER | 未读留言数 |
| `latest_favorite_title` | TEXT | 最新收藏的标题，可空 |
| `updated_at` | INTEGER | 数据时间戳（毫秒） |

小组件展示 `updated_at` 的相对时间（「3 分钟前更新」），让「数据是否新鲜」可见。

## 8.5 UI 与交互

- 布局：左侧品牌色竖条 + 三个数字块（大号数字 + 小号标签）+ 底部一行「最新收藏」+ 右上角刷新按钮；
- 深色模式：跟随系统（`RemoteViews` 用 `@color` 资源，不用硬编码颜色）；
- 点击：
  - 数字「收藏」→ `csm://market/favorites`
  - 「未读」→ `csm://market/messages`
  - 「发布」→ `csm://market/my_listings`
  - 整块 → 打开主 App 首页
- 深链用 `PendingIntent.getActivity` + `Intent.ACTION_VIEW` + `FLAG_IMMUTABLE`（Android 12+ 必须显式声明可变性）。

## 8.6 刷新策略

| 触发 | 频率 | 实现 |
| --- | --- | --- |
| 数据变更 | 实时 | 主 App `notifyChange` → Provider 监听 → `AppWidgetManager.updateAppWidget` |
| 手动 | 用户点击 | 刷新按钮的 PendingIntent 触发 `updateAll` |
| 兜底定时 | 6 小时 | WorkManager 周期任务（`ExistingPeriodicWorkPolicy.KEEP`） |
| 系统事件 | 开机/时区变化 | `ACTION_BOOT_COMPLETED`、`ACTION_TIME_CHANGED` 里重排刷新 |

不做 1 分钟级轮询：小组件耗电敏感，且校园场景下数据变化不频繁。

## 8.7 异常与降级（课程硬性要求）

| 情况 | 表现 |
| --- | --- |
| 主 App 未登录 | 数字显示 `—`，底部提示「打开 App 登录后查看」 |
| 主 App 被卸载 | Provider 查询抛异常 → 捕获后显示「请先安装校园集市」引导 |
| 数据库为空 | 显示 `0` 与「还没有收藏，去逛逛」 |
| 查询超时/异常 | 保留上一次成功的数据，底部标注「数据可能不是最新」 |
| 主 App 版本升级改了表结构 | Provider 内部做字段兼容（缺失列返回默认值），不直接崩 |

关键原则：**小组件永远不崩溃、永远不留白屏**，最差也是显示引导文案。

## 8.8 独立验收方式

1. 只装伴生模块（不装主 App）→ 显示「请先安装校园集市」，不崩溃；
2. 装主 App 并登录、收藏 2 个商品 → 小组件数字变 2；
3. 杀掉主 App 进程 → 小组件数字仍在（读的是本地库）；
4. 断网 → 数字不变，刷新后仍显示旧数据 + 「可能不是最新」；
5. 点数字 → 正确跳到主 App 对应页面。

这 5 条就是 3 分钟录屏里伴生模块那一段的脚本。

## 8.9 与主 App 的 Git 关系

同一仓库，独立模块目录：

```
csm/
├── app/           主 App
├── companion/     伴生模块（独立 applicationId: com.csm.market.wg）
└── core-data/     共享的 Room Entity 与 Provider 契约（两边都依赖）
```

- 伴生模块有独立的 `build.gradle.kts` 与 `AndroidManifest.xml`，可单独 `assembleDebug` 安装；
- 提交 13/14 只改 `companion/` 与 `core-data/`，Git 记录上能清楚看到「伴生模块」这条线；
- 不把伴生模块塞进主 App 的 `app/` 里——那样无法「独立可运行」，也不符合课程「两个可评分成果」的要求。
