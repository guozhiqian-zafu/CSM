# 04 接口设计

客户端用 Retrofit + OkHttp 访问自建的轻量后端（Ktor，随仓库提供 `server/` 目录，第 6 次提交接入）。
所有接口统一返回 JSON 信封，避免每个接口各写一套错误处理。

## 4.1 统一响应格式

```json
{ "code": 0, "message": "ok", "data": { } }
```

| code | 含义 | 客户端处理 |
| --- | --- | --- |
| 0 | 成功 | 取 `data` |
| 1001 | 参数错误 | 提示后端返回的 `message` |
| 1002 | 未登录 / 登录过期 | 清 token，跳登录 |
| 1003 | 无权限 | 提示无权限 |
| 2001 | 资源不存在 | 展示「商品已下架」 |
| 5000 | 服务端异常 | 通用错误态 + 重试 |

HTTP 状态码仍保持语义（200/400/401/403/404/500），客户端以 `code` 为主做分支，
HTTP 层异常（超时、DNS 失败、断网）由 `CsmError` 的 `Network/Timeout` 分支兜底。

## 4.2 商品

### GET `/api/products`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `page` | int | 从 1 开始 |
| `size` | int | 默认 20 |
| `category` | string? | `BOOK`/`DIGITAL`/... 不传为全部 |
| `keyword` | string? | 匹配标题与描述 |
| `minPrice` / `maxPrice` | double? | 价格区间 |
| `condition` | string? | 成色筛选 |
| `sort` | string? | `latest`（默认）/`priceAsc`/`priceDesc`/`nearby` |
| `lat` / `lng` | double? | `sort=nearby` 时必传，服务端按距离排序 |

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "page": 1, "size": 20, "total": 137, "hasMore": true,
    "items": [{
      "id": "p1001", "title": "考研数学复习全书（九成新）",
      "price": 32.0, "originalPrice": 68.0,
      "category": "BOOK", "condition": "GOOD",
      "description": "……", "location": "南苑 3 号楼",
      "publishedAt": "2026-10-28T10:12:00+08:00",
      "seller": { "id": "u12", "name": "李同学" },
      "cover": "https://cdn.example.com/p/1001_1.jpg",
      "images": ["https://cdn.example.com/p/1001_1.jpg"],
      "suggestPrice": 29.9, "isBargain": true
    }]
  }
}
```

`suggestPrice` / `isBargain` 由服务端下发，保证多端一致；客户端本地也保留了同一套纯函数实现，
用于离线场景与发布时的即时反馈（见 `docs/06`）。

### GET `/api/products/{id}`

返回单个商品完整信息，含图片数组与卖家信息。404 时 `code=2001`。

### POST `/api/products`（multipart）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | text | 1–40 字 |
| `price` | text | > 0 |
| `originalPrice` | text? | 可空 |
| `category` / `condition` | text | 枚举名 |
| `description` | text | ≤ 500 字 |
| `location` | text | 校区/楼栋 |
| `images` | file[] | JPEG，已由客户端压缩并脱敏 |

服务端限制：单文件 ≤ 2 MB、最多 9 张、仅接受 `image/jpeg`。
超出返回 `code=1001` 并指出具体字段。响应返回创建后的商品（含 `id` 与图片 URL）。

### DELETE `/api/products/{id}`

下架自己的商品；非本人返回 403。

## 4.3 收藏

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/favorites?page=&size=` | 我的收藏（分页） |
| PUT | `/api/favorites/{productId}` | 收藏（幂等） |
| DELETE | `/api/favorites/{productId}` | 取消收藏（幂等） |

客户端策略：本地 Room 先写（乐观更新），网络失败时保留本地状态并加入待同步队列，
下次进入收藏页时重试——保证断网也能点收藏。

## 4.4 留言

### GET `/api/products/{id}/messages?page=`

```json
{ "code": 0, "data": { "items": [
  { "id": "m1", "productId": "p1001", "fromUser": "王同学", "content": "还在吗？",
    "createdAt": "2026-10-30T09:00:00+08:00", "isMine": false }
] } }
```

### POST `/api/products/{id}/messages`

请求 `{ "content": "还在吗？" }`，1–200 字，频率限制：同一用户 10 秒内最多 1 条（超限 `code=1001`）。

### GET `/api/messages/mine`

「我的留言」会话列表：一个商品一条，按最后一条留言时间倒序。未读数只统计别人发来且 `read = 0` 的留言。

```json
{ "code": 0, "data": [
  { "productId": "p1793", "productTitle": "考研数学复习全书（九成新）", "cover": null,
    "lastContent": "在的，可以约在图书馆门口看货。",
    "lastAt": "2026-11-03T09:12:00+08:00", "unreadCount": 1 }
] }
```
### GET `/api/messages/unread-count`

返回 `{ "count": 3 }`，供「我的」页红点与**伴生模块桌面小组件**读取。

## 4.5 定价统计

### GET `/api/price-stats?category=BOOK`

```json
{ "code": 0, "data": {
  "category": "BOOK", "median": 35.0, "p25": 20.0, "p75": 55.0,
  "sampleCount": 42, "updatedAt": "2026-11-01T08:00:00+08:00"
} }
```

服务端每小时聚合一次。客户端缓存到 `price_stats` 表，发布页优先用缓存（离线也能给建议价）。

## 4.6 认证（简化）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 学号 + 密码，返回 `token` 与用户信息 |
| GET | `/api/auth/me` | 校验 token，返回当前用户 |

token 放 `Authorization: Bearer <token>`，由 OkHttp 拦截器统一附加；
收到 `code=1002` 时清 token 并跳登录页。课程项目不做第三方登录，避免额外依赖与账号风险。

## 4.7 客户端网络层约定

- 超时：连接 10s、读 20s、写 30s（上传图片较慢）；
- 重试：仅对 GET 做 1 次自动重试，POST 交给用户手动重试（避免重复创建）；
- 日志：debug 构建打印请求/响应行数与耗时，release 关闭；
- 缓存：`Cache-Control: max-age=60`，首页列表允许 1 分钟内的 HTTP 缓存；
- 图片 URL 与业务数据分离，图片走 CDN/静态目录，列表接口只返回 URL，避免 JSON 过大。

## 4.8 接口与页面的对应

| 页面 | 使用接口 |
| --- | --- |
| 首页列表 | `GET /api/products`、`GET /api/price-stats` |
| 详情 | `GET /api/products/{id}`、`PUT/DELETE /api/favorites/{id}` |
| 发布 | `GET /api/price-stats`、`POST /api/products` |
| 收藏 | `GET /api/favorites` |
| 留言 | `GET/POST /api/products/{id}/messages`、`GET /api/messages/mine`、`GET /api/messages/unread-count` |
| 我的 | `GET /api/auth/me`、`GET /api/products?mine=true` |

## 4.9 服务端实现现状（第 5 次提交）

`server/` 是随仓库提交的 Ktor + SQLite 参考实现，用于课程演示与联调，不是真实上线服务：

| 项 | 取值 |
| --- | --- |
| 技术栈 | Ktor 2.3.12（Netty）+ kotlinx.serialization + sqlite-jdbc 3.46.1.0 |
| 端口 | 默认 `8080`，可用环境变量 `CSM_PORT` 覆盖（本机 8080 被占用时演示用 `18080`） |
| 数据库 | `server/data/csm.db`，首次启动自动建表并灌 14 条中文样例；已加入 `.gitignore` |
| 入口 | `server/src/main/kotlin/com/csm/server/Application.kt`（`mainClass = com.csm.server.ApplicationKt`） |
| 启动 | `gradle :server:run`（在仓库根目录执行） |

已实现并与文档一致的接口：

- `GET /health` → `{"status":"ok","service":"csm-market"}`
- `GET /api/products`：`page`（默认 1，非法值回落 1）、`size`（默认 20，上限 50）、
  `category`、`keyword`（标题/描述模糊匹配）、`minPrice`/`maxPrice`、`condition`、
  `sellerId`（只看某个卖家发布的，客户端「我的发布」传 `u-me`，接入登录后换成真实 userId）、
  `sort=latest|priceAsc|priceDesc`（白名单，非法值回落 `latest`）
- `GET /api/products/{id}`：不存在或已下架 → HTTP 404 + `code 2001`
- `POST /api/products`：成功 HTTP 201；校验失败 HTTP 400 + `code 1001`，
  message 精确到字段（`标题不能为空` / `标题不能超过 40 个字` / `价格必须大于 0` /
  `价格看起来不太合理，请检查` / `分类取值非法：X` / `成色取值非法：X` / `描述不能超过 500 个字` /
  `缺少必填字段：a、b`）
- `DELETE /api/products/{id}`：软删除（`status='TAKEN_DOWN'`），再次查询返回 404
- `GET /api/price-stats?category=`：返回 `median/p25/p75/sampleCount`，分类为空时统计全部在售商品

列表与详情响应里的 `suggestPrice`、`isBargain` 由服务端统一计算（算法见 `docs/06` 6.5），
客户端不重复实现规则，保证「详情页建议价」与「列表捡漏标签」永远一致。
### 4.10 图片上传（第 8 次提交实现）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/uploads` | multipart/form-data，字段名 `file`；返回 `{ "url": "/uploads/<uuid>.jpg", "bytes": 12345 }` |
| GET | `/uploads/{name}` | 读取已上传图片，`Content-Type` 由扩展名推断 |

约束与实现：

- 扩展名白名单 `jpg` / `jpeg` / `png` / `webp`，其它一律 `400 + code 1001`；
- 单张上限 5MB（`MAX_UPLOAD_BYTES`），超出返回「图片不能超过 5MB」；
- 落盘名使用 `UUID.randomUUID()` + 原扩展名，避免中文文件名与重名覆盖；
- `GET /uploads/{name}` 先校验名字里不含 `/`、`\`、`..`，防止目录穿越；
- 文件目录 `server/data/uploads`（可用 `-Dcsm.uploads` 覆盖），已加入 `.gitignore`；
- 发布商品时把这些相对地址写进 `POST /api/products` 的 `images` 数组，服务端取第一张作为 `cover`。

客户端对应实现：`util/ImageCompressor` 先把图片压到长边 1280、质量 82 并重编码（顺带丢掉 EXIF 里的 GPS），
再由 `DefaultProductRepository.publish()` 逐张上传，全部成功后才创建商品——避免买家刷到「有商品没图」的空壳。
