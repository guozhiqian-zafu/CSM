# 03 系统设计与数据模型

## 3.1 架构总览

单 Activity + 多 Fragment（Navigation），每个页面对应一个 ViewModel，
数据层通过 Repository 暴露 `Flow` / `suspend` 函数给上层，UI 层不直接接触 Retrofit 或 Room。

```
┌─────────────────────────────────────────────┐
│ UI 层      Fragment + ViewBinding + Adapter │
│            （只读 ViewModel 的 UiState）      │
├─────────────────────────────────────────────┤
│ 状态层      ViewModel（viewModelScope）      │
│            UiState: Loading/Empty/Error/Ok   │
├─────────────────────────────────────────────┤
│ 数据层      Repository                      │
│            ├── Local：Room + DataStore       │
│            └── Remote：Retrofit + OkHttp     │
├─────────────────────────────────────────────┤
│ 领域层      pricing / image / geo            │
│            （纯 Kotlin，可单测，无 Android）  │
└─────────────────────────────────────────────┘
```

要点：

- **单一数据源**：列表永远先渲染 Room 缓存，网络成功后回写 Room，UI 只订阅 Room 的 Flow。
  这样断网时列表不空，也让「附近好物」这类额外计算只做一次。
- **领域层无 Android 依赖**：定价算法与距离计算是纯函数，直接 JVM 单测（提交 14 会补覆盖率）。
- **错误模型统一**：网络层把 HTTP / IO / 解析异常映射成 `CsmError` 密封类，
  UI 只根据错误类型显示文案，不判断异常类型。

## 3.2 页面结构与导航

```
MainActivity（唯一 Activity，底部导航）
├── homeFragment        首页列表（列表 → 详情）
│   └── action_home_to_detail ──► detailFragment(productId)
├── publishFragment     发布（相册/拍照 → 表单 → 上传）
├── favoritesFragment   我的收藏（空态引导）
├── profileFragment     我的（我发布的 / 我的留言 / 设置）
├── searchFragment      搜索（关键词 + 价格区间 + 成色）        ← 提交 7
└── messagesFragment    留言列表 / 留言详情                     ← 提交 11
```

底部导航只在四个一级页面显示；进入详情等二级页面自动隐藏（`addOnDestinationChangedListener`）。
这样避免用户在详情页误触底部栏，也让返回栈语义清晰。

## 3.4 数据模型

### 3.4.1 领域模型（当前已实现）

```kotlin
enum class ProductCategory(val label: String, val basePrice: Int) {
    BOOK("教材书籍", 35), DIGITAL("数码电子", 320), DAILY("生活用品", 25),
    SPORTS("运动户外", 90), CLOTHING("服饰鞋包", 60), OTHER("其他", 40)
}

enum class ProductCondition(val label: String, val factor: Double) {
    NEW("全新", 1.15), LIKE_NEW("几乎全新", 1.05), GOOD("轻微使用", 0.95),
    FAIR("明显使用", 0.80), POOR("有瑕疵", 0.65)
}

data class Product(
    val id: String,
    val title: String,
    val price: Double,
    val originalPrice: Double?,
    val category: ProductCategory,
    val condition: ProductCondition,
    val description: String,
    val location: String,
    val publishedMinutesAgo: Int,
    val sellerName: String,
    @DrawableRes val coverRes: Int
)
```

`basePrice` 与 `factor` 是定价算法的输入参数，不放进 UI 层常量，避免算法被硬编码散落各处。

### 3.4.2 Room 表设计（提交 5 实现）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `products` | id(PK), title, price, original_price, category, condition, description, location, published_at, seller_id, seller_name, status | 服务端商品的本地缓存，`status` 为 ON_SALE / SOLD / REMOVED |
| `product_images` | id(PK), product_id(FK), remote_url, local_path, sort_order, width, height | 一商品多图，`local_path` 用于离线预览与重试上传 |
| `favorites` | product_id(PK), created_at | 本地收藏，与服务端对齐 |
| `messages` | id(PK), product_id, from_user, content, created_at, is_read | 留言，`is_read` 供伴生模块统计未读 |
| `price_stats` | category(PK), median_price, p25, p75, sample_count, updated_at | 定价算法的同类目统计，服务端下发 |
| `search_history` | keyword(PK), searched_at | 最近搜索（DataStore 亦可，放 Room 便于分页） |

索引：`products(category, published_at)`、`messages(product_id, created_at)`、`favorites(created_at)`。

## 3.5 状态模型

```kotlin
sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Empty(val reason: String?) : UiState<Nothing>
    data class Error(val error: CsmError, val cached: T? = null) : UiState<Nothing>
}
```

`Error` 里带 `cached` 是关键设计：断网时既显示错误提示，又能继续显示缓存数据，
不会因为一次请求失败就把已加载的列表清空。

```kotlin
sealed class CsmError(val message: String) {
    class Network(val cause: Throwable) : CsmError("网络连接失败，请检查网络")
    class Timeout(val cause: Throwable) : CsmError("请求超时，请稍后重试")
    class Server(val code: Int, val body: String?) : CsmError("服务器开小差了（$code）")
    class Unauthorized : CsmError("登录已过期，请重新登录")
    class Unknown(val cause: Throwable) : CsmError("未知错误")
}
```

## 3.6 关键技术决策

| 决策 | 原因 |
| --- | --- |
| 单 Activity + Navigation，而非多 Activity | 底部导航与返回栈天然一致；深链（伴生模块用）只需一个入口；共享 ViewModel 更容易 |
| ViewBinding 而非 findViewById / DataBinding | 编译期类型安全，无反射开销；DataBinding 对课程规模是过度设计 |
| 列表用 `ListAdapter + DiffUtil` | 分页与刷新时只更新变化的条目，避免闪烁和滚动位置丢失 |
| 列表先读 Room 再请求网络（stale-while-revalidate） | 断网可用；「附近好物」不必每次重新算 |
| 定价算法放 `domain` 纯函数 | 可单测、可复用于伴生模块，不依赖 Context |
| 后端自建轻量服务而非 Firebase | 课程要求「原生 Android」；自建服务能展示接口设计与错误处理，也避免外部账号依赖 |

## 3.7 权限设计

| 权限 | 申请时机 | 拒绝后的降级 |
| --- | --- | --- |
| `CAMERA` | 点「拍照」时申请 | 隐藏拍照入口，只保留「从相册选择」，发布仍可完成 |
| `ACCESS_FINE_LOCATION` / `COARSE` | 进入首页点「按距离排序」时 | 顶部提示条 + 回退默认排序，可点提示去系统设置 |
| `POST_NOTIFICATIONS`（Android 13+） | 进入「消息」页时申请 | 不弹通知，页内红点仍在 |

统一封装 `PermissionHelper`：一次申请、`shouldShowRequestPermissionRationale` 判断、
「不再询问」时引导到设置页，避免每个页面各写一套。
