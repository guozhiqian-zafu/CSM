# 06 个性化功能设计

三个个性化功能不是独立 demo，而是同一条链路上的三段：
**图片质量决定商品可信度 → 定价算法给出参考价 → 距离告诉买家值不值得跑一趟。**

---

## 6.1 必做 ①：智能定价助手

### 6.1.1 要解决的问题

学生第一次卖二手，最常见的两种失误：

- 定价过高：挂一个月没人问，最后自己降价，或者干脆不卖了；
- 定价过低：几分钟被秒，事后才发现亏了。

平台侧希望价格尽量贴近真实成交区间，买家侧的「捡漏」标签也依赖同一套基准价。

### 6.1.2 基准价从哪来

同一类目下已成交/在售商品的价格**中位数**（不用平均数，避免个别极端高价拉偏）：

```
base(category) = median({ p.price | p.category == category, p.status in (ON_SALE, SOLD) })
```

数据不足（样本 < 5）时回退到类目先验价 `ProductCategory.basePrice`，
并在 UI 上弱化展示（显示「样本较少，仅供参考」），避免给出虚假的精确感。

| 类目 | 先验基准价（元） |
| --- | --- |
| 教材书籍 | 35 |
| 数码电子 | 320 |
| 生活用品 | 25 |
| 运动户外 | 90 |
| 服饰鞋包 | 60 |
| 其他 | 40 |

### 6.1.3 成色系数

```kotlin
enum class ProductCondition(val label: String, val factor: Double) {
    NEW("全新", 1.15), LIKE_NEW("几乎全新", 1.05), GOOD("轻微使用", 0.95),
    FAIR("明显使用", 0.80), POOR("有瑕疵", 0.65)
}
```

「全新」允许高于基准价 15%（同款全新在校园里比电商便宜仍有吸引力），
「有瑕疵」打到 65%。系数放在枚举里而不是散落在公式里，便于后续用真实成交数据校准。

### 6.1.4 挂牌时长折价

挂得越久，卖家心理价位越低，这个信号用于**列表侧的估价**（发布侧不适用，因为刚发布时长为 0）：

```
urgency(daysListed) = 1 - min(0.15, 0.01 × daysListed)     // 最多折 15%
```

### 6.1.5 建议价与区间

```
suggest = base(category) × condition.factor × urgency(daysListed)
range   = [suggest × 0.85, suggest × 1.15]
```

给出区间而不是单一数字，是因为二手定价本身有弹性；区间让用户有「自己拍板」的空间，
而不是被算法牵着走。

**算例**：九成新的教材（GOOD 0.95），类目中位价 35，挂了 10 天

```
urgency = 1 - min(0.15, 0.10) = 0.90
suggest = 35 × 0.95 × 0.90 = 29.9  ≈ 29.9 元
range   = [25.4, 34.4]
```

### 6.1.6 定价合理性评分

用户填了价格 `p` 后，计算相对偏差并映射到 0–100 分：

```
deviation = (p - suggest) / suggest
score     = clamp(round(100 - 200 × |deviation|), 0, 100)
```

| 偏差 | 分数 | 结论文案 |
| --- | --- | --- |
| ≤ −30% | 40 以下 | 偏低，可能亏了 |
| −30% ~ −10% | 60–80 | 略低于参考价，容易卖出 |
| −10% ~ +10% | 80–100 | 合理，建议保持 |
| +10% ~ +30% | 60–80 | 略高于参考价，可小幅下调 |
| > +30% | 40 以下 | 过高，可能长时间无人问津 |

分数在发布页随「价格 / 分类 / 成色」变化**实时刷新**，并给出一句可操作的建议
（不是只报分数），例如「参考价 25–34 元，你填的 90 元偏高，建议降到 30 元左右」。

### 6.1.7 「捡漏」标记

列表中对满足下面条件的商品打标签：

```
p.price ≤ suggest × 0.70     // 低于建议价三成
```

只作为提示，不做真伪判断；同时要求样本数 ≥ 5，避免样本太少误标。

### 6.1.8 边界情况

| 情况 | 处理 |
| --- | --- |
| 类目样本不足 | 回退先验价 + 「样本较少」提示 |
| 价格为 0 或非法 | 不参与统计，不显示评分 |
| 用户填了原价 | 原价只做展示与「折扣力度」参考，不参与估价 |
| 中位数计算 | 偶数个样本取中间两个的均值，价格保留 1 位小数 |

### 6.1.9 代码位置与可测性

- `domain/pricing/PriceEstimator.kt`：纯函数，入参 `(category, condition, daysListed, samples)`；
- `domain/pricing/PriceRating.kt`：`rate(price, suggest) -> PriceRating(score, tier, advice)`；
- 无 Android 依赖，直接 JVM 单测覆盖：样本不足、偶数中位数、极端偏差、0 价格等用例。

## 6.2 必做 ②：图片处理流水线

### 6.2.1 为什么需要

手机直出照片通常 3–8 MB。九张图一次上传，在校园网下很容易失败；
同时照片里可能带 GPS 坐标（宿舍楼、教室），直接上传是隐私泄漏。

### 6.2.2 流水线

```
拍照/选图 → 读取方向(EXIF) → 按长边等比缩放 → JPEG 压缩 → 重新写回旋转 → 剥离 EXIF → 保存临时文件 → 上传
```

| 步骤 | 参数/做法 | 说明 |
| --- | --- | --- |
| 采样解码 | `inJustDecodeBounds` 先读尺寸，再按 `inSampleSize` 降采样 | 避免把 4000×3000 全量读进内存导致 OOM |
| 缩放 | 长边 1280px，等比 | 详情页大图也够清晰 |
| 压缩 | JPEG quality 82 | 实测 3–5 MB → 200–400 KB |
| 方向 | 读 `TAG_ORIENTATION`，先旋转再压缩 | 否则竖拍图在详情页会横躺 |
| EXIF 脱敏 | 只保留 Orientation，其余（GPS、Make、Model、DateTime）全部移除 | 隐私 + 减小体积 |
| 线程 | `Dispatchers.Default` 处理，`Dispatchers.IO` 落盘 | 不阻塞主线程 |
| 命名 | `UUID + .jpg`，落 `cacheDir/uploads/` | 缓存目录，系统可回收 |

### 6.2.3 上传策略

- **逐张上传**，不是一次性打一个大包：单张失败只重试那一张，不影响已成功的；
- 进度 = 已成功张数 / 总张数，UI 显示「3/9 上传中」+ 进度条；
- 失败重试：指数退避（1s、2s、4s），最多 3 次，仍失败则标记该图「上传失败，点击重试」；
- 取消：用户离开页面时取消协程，已上传的保留，下次进入可续传（按本地文件是否存在判断）。

### 6.2.4 验收方式

录屏里会对比「处理前 4.2 MB / 处理后 260 KB」，并展示处理后的照片在详情页正常竖显、
用工具查看确认 EXIF 中不再有 GPS 字段。

## 6.3 自选：附近好物

### 6.3.1 距离计算

球面两点距离用 Haversine（不引入地图 SDK，避免 Google Maps Key 依赖）：

```
a = sin²(Δφ/2) + cos φ1 · cos φ2 · sin²(Δλ/2)
d = 2R · atan2(√a, √(1−a)),  R = 6371 km
```

结果按距离升序排序，`< 1 km` 显示米（如「320 m」），否则显示公里（「1.4 km」）。

### 6.3.2 权限降级（课程重点考察项）

| 状态 | 行为 |
| --- | --- |
| 未申请 | 用户点「按距离排序」时才申请（不提前打扰） |
| 已授权 | 取一次位置（`FusedLocationProvider`，`PRIORITY_BALANCED`），显示距离与排序 |
| 拒绝一次 | 顶部提示条：「未获得定位权限，已按发布时间排序」，条上带「去开启」按钮 |
| 拒绝且不再询问 | 提示条改为「去设置开启定位」，点击跳系统设置页 |
| 定位服务关闭 | 提示「请打开系统定位」，仍可用其他排序 |

关键点：**拒绝权限不阻断任何核心流程**，列表照常显示，只是少了距离信息。

### 6.3.3 位置缓存

位置存 DataStore（`last_location_lat/lng/at`），有效期 10 分钟，
避免每次进首页都重新定位耗电；超过有效期或用户手动下拉刷新时才重新请求。

## 6.4 三个功能之间的关系

```
发布：拍照 → 压缩/脱敏 → 上传 → 定价助手给建议价
浏览：列表 → 捡漏标签（用同一套基准价） → 距离排序（近的优先看）
```

定价算法的基准价来自「同类目商品池」，这个池子正是列表页展示的数据；
所以算法不是写死的常量表，而是随平台数据变化而更新的。
这一点是它与「随便加个 if-else 算个价」的本质区别，也是答辩时会被追问的地方。
